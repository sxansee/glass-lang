# Glass Studio и .NET-часть

IDE для языка Glass: редактор кода, пошаговый отладчик, **схема кучи** и **инспектор объекта**
(раскладка полей в памяти, vtable) — то, ради чего язык и задуман: устройство объекта, виртуальный
вызов и сборка мусора становятся видимыми.

## Проекты

| Проект | Что это | Собирается и проверяется в контейнере (Linux) |
|---|---|---|
| `Glass.Interop` | P/Invoke-мост к `glass_capi` (`NativeMethods`, `GlassSession`) | да, на живой `libglass_capi.so` |
| `Glass.Studio.Core` | переносимое ядро IDE **без WPF**: модели, разбор JSON, раскладка схемы кучи, `DebugSession`, `MainViewModel`, инспектор | да, на живой `libglass_capi.so` |
| `Glass.Studio.Tests` | тесты ядра + XAML-линтер; обычная консольная программа, **без NuGet** | да |
| `Glass.Studio` | WPF-оболочка: XAML, редактор на AvalonEdit | **нет — только Windows** |

Идея разбиения: WPF собрать и запустить можно только на Windows, поэтому в нём оставлено минимум —
окно, XAML и «склейка» редактора с ViewModel. Всё, что можно сломать логикой (когда какая кнопка
доступна, что показать на паузе, как раскладывается схема кучи, как остановить зависшую программу),
живёт в `Glass.Studio.Core` и проверяется по-настоящему.

## Что проверено, а что нет

**Проверено автоматически** (`dotnet run -c Release` в `Glass.Studio.Tests`):

- мост `Glass.Interop` реально компилируется (`TreatWarningsAsErrors`) и каждая сигнатура вызвана на живой библиотеке;
- разбор JSON, диагностики, форматирование адресов и склонений;
- раскладка схемы кучи: цепочки, циклы, ссылка на себя, общий объект, мусор, подсветка «новое/изменено»,
  лимиты (200 узлов, длинные массивы), отсутствие перекрытий, список из 3000 звеньев без переполнения стека;
- `DebugSession`: паузы, шаги, Стоп бесконечного цикла из другого потока, защита от параллельных вызовов,
  `Dispose` во время выполнения, состояние на момент рантайм-ошибки, сборка мусора, инспектор объекта;
- `MainViewModel` целиком: состояния Editing/Running/Paused/Finished, доступность каждой команды, статусная строка,
  подсветка строки в редакторе (через заглушку), таблицы стека и переменных, точки останова (и их перенос при правке),
  файлы и подтверждение потери изменений, меню примеров, все встроенные примеры;
- **XAML-линтер** по файлам `Glass.Studio`: привязки по типам ViewModel (контекст берётся из `d:DataContext`,
  `DataType` шаблонов, `ItemsSource`, места применения стилей), права записи для TwoWay (в том числе TwoWay
  по умолчанию), bool→Visibility без конвертера, ресурсы по областям видимости и порядку объявления,
  `x:Static`/`x:Type`, обработчики событий и их сигнатуры, дубли. Линтер сам проверен «мутациями»: в копии
  настоящих файлов вносятся типичные ошибки (опечатка в свойстве, убранный `Mode=OneWay`, не тот `DataType`,
  пропавший ресурс) — и тест требует, чтобы каждую он нашёл;
- подсветка синтаксиса (`Editor/Glass.xshd`) валидна по XSD-схеме AvalonEdit, а её список слов совпадает с таблицей
  ключевых слов лексера (`src/lexer/Lexer.cpp`);
- каждый вызов AvalonEdit в `Editor/*.cs` сверен по исходникам AvalonEdit 6.3.

**НЕ проверено** (требует Windows): компиляция самого WPF-проекта (генерация кода из XAML, `InitializeComponent`)
и внешний вид. Ожидайте, что первая сборка может потребовать пары мелких правок. Вероятные места:

1. **Версия AvalonEdit.** В `Glass.Studio.csproj` стоит плавающая `6.3.*`. Если NuGet не находит —
   поставьте любую `6.3.x` из менеджера пакетов; API, по которому писался `Editor/*.cs`, — ветка 6.3.
2. **Предупреждения о nullable** в `Editor/*.cs` (AvalonEdit не размечен): это предупреждения, не ошибки.
3. **Внешний вид**: размеры и отступы подбирались «в уме». Если что-то обрезается — правится в `Themes/Glass.xaml`
   (палитра и стили) и константах `HeapMetrics` (размеры узлов схемы кучи, `Glass.Studio.Core/Heap/HeapGraph.cs`;
   рёбра считаются по тем же константам, поэтому менять их можно свободно).
4. **`KeyBinding` с `Command="{Binding ...}"`** на окне работает при выставленном `DataContext` (он выставляется в
   конструкторе `MainWindow`). Если какая-то горячая клавиша молчит — проверьте её в меню «Отладка» (те же команды).

## Как запустить тесты

Сначала собрать C++-часть (нужна `glass_capi`):

```
cmake -S . -B build
cmake --build build --config Release
```

Затем (из каталога `dotnet/Glass.Studio.Tests`):

```
dotnet run -c Release                  # все проверки
dotnet run -c Release -- мутации       # только тесты, в названии которых есть «мутации»
```

Библиотеку тесты ищут сами (`build/`, `build/Release`, `build/Debug`, `out/build/x64-*`); нестандартное место —
переменная окружения `GLASS_CAPI_PATH` (полный путь к `glass_capi.dll` / `libglass_capi.so`). Код возврата 0 —
всё зелёное. Из корня репозитория то же самое делает `scripts/test-all.ps1` (Windows) / `scripts/test-all.sh` (Linux/macOS):
собирает, прогоняет все одиннадцать C++-наборов и .NET-тесты.

## Как собрать и запустить Glass Studio (Windows)

1. Собрать `glass_capi.dll`: `cmake --build build --config Release --target glass_capi` (или открыть папку в
   Visual Studio и выполнить **Сборка → Собрать всё** — x64!). DLL только собирают: назначить её элементом
   запуска нельзя — Visual Studio ответит «Отсутствует исполняемый файл цели» (это не ошибка сборки).
2. Открыть `dotnet/Glass.sln` в Visual Studio 2022 (нужен .NET 8 SDK и рабочая нагрузка «Разработка классических
   приложений .NET»), выбрать проект `Glass.Studio` запускаемым, **F5**.
3. Сборка сама копирует `glass_capi.dll` рядом с `GlassStudio.exe` (ищет в `build\<Config>`, `build\`,
   `out\build\x64-<Config>`; своё место: `-p:GlassNativeDll=C:\путь\glass_capi.dll`). Не нашла — выдаст предупреждение сборки.
4. При запуске программа сама проверяет библиотеку и, если её нет или разрядность не та, объясняет это сообщением.
   Если Windows пишет, что не хватает `vcruntime140.dll`/`msvcp140.dll`, — поставьте Microsoft Visual C++ Redistributable (x64).

### Если что-то пошло не так

| Сообщение | Что значит |
|---|---|
| Visual Studio: «Отсутствует исполняемый файл цели… для цели glass_capi.dll» | выбрана для запуска библиотека; её нужно собрать (**Сборка → Собрать всё**), а запускать проект `Glass.Studio` из `Glass.sln` |
| Предупреждение сборки «glass_capi.dll не найдена» | C++-часть не собрана или собрана в другой конфигурации: Debug ищет `out\build\x64-Debug`, Release — `out\build\x64-Release` (и `build\<Config>`); либо укажите путь: `-p:GlassNativeDll=C:\путь\glass_capi.dll` |
| Окно при запуске «Не найдена нативная библиотека glass_capi.dll» | то же самое: DLL не лежит рядом с `GlassStudio.exe` |
| «Библиотека собрана под другую разрядность» | `glass_capi.dll` собрана как x86; пересоберите как x64 |
| «Не найдена `vcruntime140.dll`/`msvcp140.dll`» | поставьте Microsoft Visual C++ Redistributable (x64) |
| `EntryPointNotFoundException` при первом запуске программы | в DLL не экспортированы функции `glass_*`: проверьте `dumpbin /exports glass_capi.dll` (должно быть 21 имя) |

## Что умеет Glass Studio

Окно: слева — **код** (подсветка, номера строк, поле точек останова) и вкладки **Вывод / Ошибки**; справа — **куча**,
под ней **вызовы и переменные** и **инспектор объекта**.

| Клавиша | Действие |
|---|---|
| **F5** | начать отладку (до ближайшей точки останова) / продолжить |
| **Ctrl+F5** | выполнить программу целиком, не останавливаясь |
| **F10** / **F11** / **Shift+F11** | шаг с обходом / с заходом / с выходом |
| **Shift+F5** | остановить (во время выполнения — прервать зависшую программу; на паузе — закрыть сессию) |
| **F9** | поставить/снять точку останова на строке курсора (или клик по полю слева от номеров строк) |
| **Ctrl+N / O / S**, **Ctrl+Shift+S** | создать / открыть / сохранить / сохранить как |
| **Ctrl+колесо** на схеме кучи, **Ctrl+ + / − / 0** | масштаб схемы |

- **Схема кучи.** Узлы — объекты и массивы (заголовок: класс и короткий адрес; строки: поля со значениями), рёбра — ссылки
  (стрелка выходит из строки поля). Слева — «корни»: ссылочные локальные переменные всех фреймов. Подсветка:
  **красный** — мусор (на объект ничто не ссылается: он ещё в куче, но следующая сборка его освободит), **зелёная** рамка —
  новый с прошлой паузы, **янтарная** — изменился (изменённая строка тоже подсвечена). Клик по узлу, корню или ссылочной
  переменной выделяет объект вместе с его рёбрами и открывает инспектор. Кнопка **«Собрать мусор»** (то же, что `~gc` в языке)
  освобождает недостижимое — красные узлы исчезают.
- **Инспектор.** «Карта слотов» — цветные ячейки по типам полей; таблица смещение / поле / тип / байт / значение
  (то же, что печатает `~layout`: унаследованные поля первыми); **vtable** — для каждого виртуального метода, чья реализация
  реально выполнится (переопределён в классе объекта — жирным, унаследован — серым). Данные берёт у VM тот же код, что считает
  `~layout`/`~vtable`, поэтому расхождения с программой быть не может.
- **Ошибки.** Ошибки компиляции проверяются на лету (через 0,6 с после ввода) и подсвечивают строку; клик по ошибке переводит
  курсор. Ошибка выполнения (и «Стоп») сохраняют состояние на момент сбоя: видно стек, переменные и кучу — почему упало.
- Остановка зависшей программы работает всегда: выполнение идёт на пуле потоков, окно остаётся живым, а «Стоп» взводит
  атомарный флаг, который VM проверяет перед каждой инструкцией. Бесконечная рекурсия — тоже обычная ошибка, а не падение.

### Что показать на защите (сценарии)

1. **Виртуальный вызов** — пример «Виртуальный вызов (facet)»: точка останова на `s.area()` в цикле, F11 — какой класс
   исполняется на каждом круге; инспектор показывает vtable объекта и «кто реально реализует».
2. **Цепочка в куче** — «Связный список»: точка на `print(length(head))`, схема — четыре узла, стрелки `next`; F11 внутрь
   `length` — переменная `cur` ползёт по списку.
3. **Сборка мусора** — «Сборка мусора»: F10 по строкам; после `a = b` первый объект краснеет (мусор), кнопка «Собрать мусор»
   (или `~gc` в коде) — он исчезает.
4. **Интроспекция из кода** — «Интроспекция»: `~layout`, `~vtable`, `~heap` в выводе; сравнить с инспектором.

## Устройство

```
Glass.Studio (WPF: окно, XAML, AvalonEdit)          — тонкая оболочка, на Windows
        │  IEditorHost / IFileDialogs (интерфейсы — тестируются заглушками)
Glass.Studio.Core (MainViewModel, DebugSession, HeapGraphBuilder, модели)  — переносимое, тесты
        │
Glass.Interop (GlassSession ← NativeMethods, [DllImport])
        │  C API: extern "C", JSON
glass_capi.dll / libglass_capi.so  (C++: лексер → парсер → сема → байткод → VM + GC)
```

**Потоки.** `run`/`step` в нативной библиотеке блокируют вызвавший поток, а программа студента может быть `while true {}`.
Поэтому `DebugSession` выполняет команды на пуле потоков, а правило одно: пока команда выполняется, нативную сессию трогать
нельзя, кроме `RequestStop()` (атомарный флаг). Правило не на словах: `Capture`/`CollectGarbage`/`GetOutput` во время выполнения
бросают `InvalidOperationException`, точки останова синхронизируются с VM только на старте команды, `Dispose` сначала
останавливает VM и ждёт, пока команда целиком отпустит сессию (возврат из нативного вызова И чтение результата). `MainViewModel` «просыпается» после `await` на потоке интерфейса
(контекст синхронизации WPF), поэтому свойства меняются только в UI-потоке.

**Схема кучи.** `HeapGraphBuilder` строит узлы, рёбра и корни **с готовыми координатами**: слои — самый длинный путь от
корней (обратные рёбра циклов не растягивают схему), узлы внутри слоя — в порядке обнаружения, мусор — отдельной колонкой
справа. Точки выхода рёбер считаются по константам `HeapMetrics`, по которым XAML рисует строки узлов (`x:Static`), поэтому
стрелки попадают ровно в строки. Достижимость — не догадка интерфейса: флаг `reachable` приходит из VM (пробный обход от всех
корней GC, включая временные значения).

## Известные ограничения

- Схема показывает до 200 объектов (остальные считаются в подписи «не показано»), в узле — до 12 строк (длинные массивы
  заканчиваются строкой «… ещё N»), локальные переменные читаются у верхних 40 фреймов стека (глубокая рекурсия не тормозит паузу).
- Поле точек останова и подсветка строки рассчитаны на строки без переноса (в редакторе `WordWrap` выключен).
- Редактор: подсветка синтаксиса и номера строк есть, автодополнения и поиска/замены пока нет (поиск `Ctrl+F` — стандартный
  у AvalonEdit не включён).
