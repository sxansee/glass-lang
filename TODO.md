# Что осталось доделать

Состояние на момент передачи проекта «как есть». Всё, что помечено ✅, собрано и проверено тестами
(C++: 707 проверок в 11 наборах, 0 предупреждений — в том числе с `-Wall -Wextra`; .NET: 1656 проверок на живой библиотеке).

## ✅ Готово
- Язык: `print` с несколькими значениями, преобразования типов (`int()`, `double()`, `str()`, `bool()`, касты), неявное `int → double`,
  `range`, срезы и отрицательные индексы, методы массивов и строк, встроенные функции, `;` необязательна перед `}`, кириллица в строках.
- Ядро IDE (`dotnet/Glass.Studio.Core`): логгер (файл с ротацией + память), курс (24 урока, проверка решений, звёзды, прогресс),
  карточки элементов кода (справочник ≈80 записей), три новых примера, подсветка встроенных функций.
- Репозиторий: `LICENSE` (MIT), `.gitattributes`, `CONTRIBUTING.md`, `CHANGELOG.md`, `RELEASING.md`, `THIRD-PARTY-NOTICES.md`, шаблоны issue и PR,
  `dotnet/Directory.Build.props` (версия в одном месте), английский абзац и бейджи в README, `AppInfo.RepositoryUrl`; workflow `ci.yml` и
  `release.yml` написаны и проверены линтером — **но на GitHub ещё ни разу не запускались**. Тесты «репозиторий: …» следят за согласованностью
  версии/адресов/служебных файлов и за тем, чтобы `test-all.*` запускали все C++-наборы (раньше `language` молча пропускался).
- Переносимость C++ (подготовка к MSVC): чистая сборка и 707/707 под clang + libc++ (другая стандартная библиотека — ловит забытые `#include`);
  кросс-сборка под Windows (MinGW) без предупреждений: `glass_capi.dll` экспортирует все 21 функцию из `GlassApi.h`, зависит только от
  `KERNEL32`/`msvcrt` (статическая среда выполнения), `glassc.exe` собирается с кодом переключения кодовой страницы консоли. Настоящий MSVC здесь недоступен.
- Язык, «хвосты»: `else`/`catch`/`finally` с новой строки после `}`; `print(объект)` → `Класс@0x…` и пользовательский `toString()` (виртуальный, работает в
  `print`, `+`, `+=`, `str()`, `(string)`); проверка ссылочных приведений `(Dog) animal` во время выполнения; строгие правила `virtual`/`override`
  (`override` над невиртуальным и метод без `override` поверх виртуального — теперь ошибки, раньше полиморфизм молча не срабатывал).

## 5. Язык: хвосты и ограничения
- [ ] `toString()` не применяется к элементам массива при `print([объекты])` (там по-прежнему `Класс@0x…`).
- [ ] Неудачное приведение `(Dog) animal` — ошибка выполнения, завершающая программу, а не исключение, которое ловит `try/catch` (так устроены ошибки выполнения VM).
- [ ] В отладчике `stepInto` на `P()` для mold'а без своего конструктора заходит в неявный пустой конструктор (строка `mold`, глубина 2) — решить, показывать ли такой шаг студенту.
- [ ] Нет: `input()`, интерполяции строк, оператора `x in xs` (есть `contains`), тернарного `?:`, `switch`, дженериков, лямбд.
- [ ] Пустые массивы требуют явного типа: `let xs: [int] = []`.
