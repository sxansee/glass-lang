- **Язык: три тихие дыры закрыты** (раздел 5 прежней версии этого файла), в `src/sema/BodyChecker.cpp`:
  1. **Все пути возвращают значение** (`checkAllPathsReturn`): функция или метод с `-> тип` без `return` на какой-то ветке — ошибка компиляции, раньше на этой ветке молча
     возвращался `null`. Правила — «can complete normally» из Java и C#: завершают путь `return`/`throw`, блок с завершающим оператором, `if` с `else` при двух завершающих

  2. **Модификаторы доступа** (`checkMemberAccess`): `private` — только сам mold (в том числе через другой его экземпляр), `protected` — он и потомки, `public` и без модификатора — везде.
     Проверяются поля, методы и конструкторы в шести местах: `obj.метод()`/`this.метод()`, `super.метод()`, `super(...)`, поле по простому имени, `obj.поле`, создание объекта;
     `private`-поле предка не видно потомку даже по простому имени и не закрывает одноимённую функцию. `~layout` и инспектор по-прежнему показывают всё.
  3. **Вызов метода без `this.`**: в ветке «неизвестная функция» `visit(CallExpr)` подменяет вызов на `this.метод(...)` прямо в AST (компилятор байткода не менялся). Локальная переменная, поле,
     функция, mold и встроенная функция имя не отдают — поэтому метод `len()` может вызвать встроенную `len(items)`; `static`-метод по простому имени подменяется на `Mold.метод(...)`.

- **Язык: «хвосты» раздела 5** (следующая партия, тоже в чекере/компиляторе/VM):
  1. **`static` целиком.** Раньше `static let` молча становился обычным полем объекта (программа компилировалась и считала неверно), а `static fn` вызвать было нельзя. Теперь: `static let` — одна переменная
     на `mold` в статической области VM (`statics_`, корни GC; опкоды `LoadStatic`/`StoreStatic`), инициализаторы выполняет синтетическая функция `$static-init` до `main` (предок раньше потомка, внутри mold'а по порядку
     объявления; ошибка внутри — обычная ошибка выполнения до `main`); `static fn` — функция без `this`. Доступ: `Mold.член` (в том числе через потомка) или по простому имени внутри mold'а и потомков; через экземпляр,
     `this` и `super` — ошибка с подсказкой; в static-коде нет полей и методов объекта; правила доступа те же. `private`-конструктор виден static-инициализатору своего mold'а (одиночка). `~layout` статических полей не показывает.
  2. **Присваивание элементу строки** (`s[0] = ...`, в том числе `+=`) — ошибка компиляции «строки неизменяемы» с подсказкой про срезы; раньше — падение при выполнении.
  3. **Склонение в сообщениях компилятора:** «1 ошибка типизации», «2 ошибки», «5 ошибок» (`src/util/Plural.h`, он же считает «1 аргумент / 2 аргумента»).
  4. **Единый вид адресов:** `print(obj)` и `~heap` показывают `Класс@0x…`, а новая встроенная `hex(n)` печатает число так же (`hex(объект~address)`, отрицательные — `-0xff`).
  5. **Отладчик:** `stepInto` на `P()` больше не «заходит в пустой конструктор»: служебная функция `Mold$fieldinit` (вызов инициализации предка, возврат) помечена строкой 0, как prelude, — отладчик в ней не
     останавливается и кадра не показывает. Инициализаторы полей по-прежнему пользовательский код: в `let x: int = five()` заходить можно и нужно.

## 5. Язык: тихие дыры и ограничения (найдены при написании документации; большинство описаны на страницах docs/language как «пока не поддерживается»)
Порядок — по тому, как больно студенту:
- [ ] `return` / `break` / `continue` внутри `try` с `finally` — ошибка компиляции (сознательное упрощение, см. README); сообщение теперь честное.
- [ ] **`protected` проверяется по месту обращения, а не по типу ссылки.** В C# через ссылку на базовый тип `protected`-член недоступен даже потомку (CS1540); в Glass доступен
      (описано на странице «Объекты», раздел «Доступ к членам»).
- [ ] **Доступ не связан с `override` и контрактом `facet`.** `override` может сузить доступ (`public virtual` → `private override`), а метод, реализующий `facet`, может быть
      `private` — через тип `facet` он вызывается, через тип `mold` нет. В C# оба случая — ошибка компиляции.
- [ ] `toString()` не применяется к элементам массива при `print([объекты])` (там по-прежнему `Класс@0x…`). Сознательно не делается: преобразование в строку для массива — нативный код, а `toString` — код на Glass, значит
      нужен повторный вход в интерпретатор из нативного (исключения внутри `toString`, шаги отладчика, GC) либо генерация вспомогательных функций во всех четырёх конвейерах сборки. Обход — цикл или `join`.
- [ ] Неудачное приведение `(Dog) animal` — ошибка выполнения, завершающая программу, а не исключение, которое ловит `try/catch` (так устроены все ошибки выполнения VM).
- [ ] Нет: `input()`, интерполяции строк, оператора `x in xs` (есть `contains`), тернарного `?:`, `switch`, дженериков, лямбд.
- [ ] Пустые массивы требуют явного типа: `let xs: [int] = []`.

## 7. UI и UX — после всех остальных задач (задание владельца: полностью и основательно)
Берёмся, когда закрыты разделы 1–6 (кроме тех, что зависят от владельца: скриншоты, релиз, текст диплома). Это не «косметика в конце», а отдельная работа на всю оболочку; план уточняется перед началом, исходный набросок:
- [ ] **Аудит сценариев студента** на живой Windows: первый запуск → урок курса → своя программа → ошибка компиляции → отладка → память (`~layout`, `~heap`, GC). Где человек останавливается, не понимает, куда нажать, или не видит результата.
- [ ] **Редактор:** подчёркивание ошибки в самом месте (сейчас подсвечивается строка) и подсказка по наведению на ошибку; замена в поиске; «перейти к строке»; сообщения компилятора — языком студента.
- [ ] **Отладчик:** управление шагами и горячие клавиши, текущая строка, стек, переменные (в том числе `static`-поля), значения по наведению, понятные состояния «не запущено / пауза / завершено / ошибка».
- [ ] **Визуализация памяти:** граф кучи, раскладка объекта, vtable — читаемость, подписи и адреса в hex, масштаб и перемещение, анимация шага сборщика мусора, цвета и обозначения «достижим / мусор».
- [ ] **Курс:** прогресс, подсказки, проверка решений, понятные формулировки ошибок.
- [ ] **Общее:** тёмная и светлая темы, шрифты, отступы и сетка, состояния «пусто / загрузка / ошибка», клавиатура и фокус, контраст, масштаб DPI, сохранение раскладки окон, единообразие кнопок и значков, тексты интерфейса.
