- **Язык: три тихие дыры закрыты** (раздел 5 прежней версии этого файла), в `src/sema/BodyChecker.cpp`:
  1. **Все пути возвращают значение** (`checkAllPathsReturn`): функция или метод с `-> тип` без `return` на какой-то ветке — ошибка компиляции, раньше на этой ветке молча
     возвращался `null`. Правила — «can complete normally» из Java и C#: завершают путь `return`/`throw`, блок с завершающим оператором, `if` с `else` при двух завершающих
     ветках, `while true` без своего `break`, `try`/`catch`/`finally`; `for` и прочие `while` — нет.
  2. **Модификаторы доступа** (`checkMemberAccess`): `private` — только сам mold (в том числе через другой его экземпляр), `protected` — он и потомки, `public` и без модификатора — везде.
     Проверяются поля, методы и конструкторы в шести местах: `obj.метод()`/`this.метод()`, `super.метод()`, `super(...)`, поле по простому имени, `obj.поле`, создание объекта;
     `private`-поле предка не видно потомку даже по простому имени и не закрывает одноимённую функцию. `~layout` и инспектор по-прежнему показывают всё.
  3. **Вызов метода без `this.`**: в ветке «неизвестная функция» `visit(CallExpr)` подменяет вызов на `this.метод(...)` прямо в AST (компилятор байткода не менялся). Локальная переменная, поле,
     функция, mold и встроенная функция имя не отдают — поэтому метод `len()` может вызвать встроенную `len(items)`; `static`-методы не подменяются.
  Проверено: +113 C++-проверок (714 → 827), 36 мутаций (каждое правило, каждая точка вызова, приоритеты) — все убиты нужными тестами; уроки курса, документация и примеры ничего из этого не ломают.

## 5. Язык: тихие дыры и ограничения (найдены при написании документации; большинство описаны на страницах docs/language как «пока не поддерживается»)
Порядок — по тому, как больно студенту:
- [ ] **`static fn`** разбирается, но вызвать нельзя ни как `Mold.f()`, ни из соседних методов.
- [ ] **Присваивание элементу строки** (`s[0] = "x"`) падает при выполнении с бессмысленным «присваивание элементу на null» вместо ошибки типов при компиляции.
- [ ] `return` / `break` / `continue` внутри `try` с `finally` — ошибка компиляции (сознательное упрощение, см. README); сообщение теперь честное.
- [ ] Сообщения компилятора: «1 ошибок типизации» — нужно склонение по числу.
- [ ] Адреса показываются непоследовательно: `print(obj)` — в hex (`Dog@0x…`), `~heap` — в десятичном виде (`Box@2044…`), `~address` — числом.
- [ ] **`protected` проверяется по месту обращения, а не по типу ссылки.** В C# через ссылку на базовый тип `protected`-член недоступен даже потомку (CS1540); в Glass доступен
      (описано на странице «Объекты», раздел «Доступ к членам»).
- [ ] **Доступ не связан с `override` и контрактом `facet`.** `override` может сузить доступ (`public virtual` → `private override`), а метод, реализующий `facet`, может быть
      `private` — через тип `facet` он вызывается, через тип `mold` нет. В C# оба случая — ошибка компиляции.
- [ ] `toString()` не применяется к элементам массива при `print([объекты])` (там по-прежнему `Класс@0x…`).
- [ ] Неудачное приведение `(Dog) animal` — ошибка выполнения, завершающая программу, а не исключение, которое ловит `try/catch` (так устроены все ошибки выполнения VM).
- [ ] В отладчике `stepInto` на `P()` для mold'а без своего конструктора заходит в неявный пустой конструктор (строка `mold`, глубина 2) — решить, показывать ли такой шаг студенту.
- [ ] Нет: `input()`, интерполяции строк, оператора `x in xs` (есть `contains`), тернарного `?:`, `switch`, дженериков, лямбд.
- [ ] Пустые массивы требуют явного типа: `let xs: [int] = []`.
