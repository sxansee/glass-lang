# Интроспекция: заглянуть в память

Главная идея Glass — сделать видимым то, что в других языках спрятано: как объект лежит в памяти, как работает виртуальный вызов, что делает сборщик мусора. Для этого в язык встроены операторы `~layout`, `~vtable`, `~address`, `~heap` и `~gc`. Они часть языка, а не отладчика: работают в обычной программе.

## `~layout` — как устроен объект

`объект~layout` показывает поля объекта: имя, смещение (в слотах) и размер. Поля предка идут первыми, поля потомка — следом, поэтому код, работающий с `Animal`, находит `name` и `age` на одних и тех же местах у любого потомка.

## `~vtable` — как работает виртуальный вызов

`объект~vtable` показывает таблицу виртуальных методов класса: имя метода → реализация, которая будет вызвана. `Dog.speak` заменил `Animal.speak`; обычного метода `eat` в таблице нет — он не виртуален и вызывается напрямую.

```glass run
mold Animal {
    let name: string
    let age: int

    Animal(n: string, a: int) {
        name = n
        age = a
    }

    virtual fn speak() -> string {
        return "..."
    }

    fn eat() -> string {
        return "ест"
    }
}

mold Dog : Animal {
    let breed: string

    Dog(n: string, a: int, b: string) {
        super(n, a)
        breed = b
    }

    override fn speak() -> string {
        return "Гав"
    }
}

fn main() {
    let d = Dog("Рекс", 3, "овчарка")
    print(d~layout)
    print(d~vtable)
}
```

```output
layout(Dog): name@0 (8 байт), age@1 (8 байт), breed@2 (8 байт)
vtable(Dog): speak -> Dog.speak
```

## `~address` — один и тот же объект?

`объект~address` — адрес объекта в куче, число. Два имени одного объекта дают один адрес; два разных объекта с одинаковым содержимым — разные. `print(объект)` без `toString` показывает тот же адрес в шестнадцатеричном виде (`Box@0x…`).

```glass run
mold Box {
    let v: int

    Box(x: int) {
        v = x
    }
}

fn main() {
    let a = Box(1)
    let b = a
    let c = Box(1)
    print(a~address == b~address, a~address == c~address)
}
```

```output
true false
```

## `~heap` и `~gc` — куча и сборщик мусора

`~heap` — снимок кучи: сколько объектов живо и какие. `~gc` — запустить сборку мусора немедленно (значения не возвращает). Сборщик устроен как mark-and-sweep: он помечает всё, до чего можно добраться от локальных переменных и стека, а остальное освобождает. Поэтому объект, на который не осталось ссылок, исчезает из кучи после сборки. Сам сборщик тоже запускается, когда куча заметно вырастает, — `~gc` нужен, чтобы увидеть работу сборщика в нужный момент.

В выводе адреса заменены на `<адрес>`: настоящие меняются от запуска к запуску.

```glass run
mold Box {
    let v: int

    Box(x: int) {
        v = x
    }
}

fn main() {
    let a = Box(1)
    let b = Box(2)
    print(~heap)
    b = null
    ~gc
    print(~heap)
}
```

```output
heap(2 объект(ов)): Box@<адрес>, Box@<адрес>
heap(1 объект(ов)): Box@<адрес>
```

Результаты `~layout` и `~vtable` — тоже обычные объекты в куче (`LayoutInfo`, `VTableInfo`): пока на них есть ссылка, `~heap` их показывает, как любой другой объект.

## Где это видно в IDE

В Glass Studio те же сведения показаны графически: схема кучи со стрелками ссылок, инспектор выбранного объекта с раскладкой его полей и таблицей vtable, панель переменных и стека — см. [описание IDE](../ide.md).
