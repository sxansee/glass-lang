# Функции

Функция объявляется как `fn имя(параметры) -> тип { ... }`. Тип результата пишется после `->`; без него функция ничего не возвращает. Порядок объявления не важен: `main` может вызывать функции, описанные ниже.

```glass run
fn main() {
    print(twice(4))
    greet("Ада")
}

fn twice(x: int) -> int {
    return x * 2
}

fn greet(name: string) {
    print("Привет,", name)
}
```

```output
8
Привет, Ада
```

## Рекурсия

Функция может вызывать сама себя. Не забудьте условие остановки.

```glass run
fn factorial(n: int) -> int {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

fn fibonacci(n: int) -> int {
    if n < 2 { return n }
    return fibonacci(n - 1) + fibonacci(n - 2)
}

fn main() {
    print(factorial(10))
    print(factorial(20))
    print(fibonacci(15))
}
```

```output
3628800
2432902008176640000
610
```

## Как передаются аргументы

Числа, логические значения и строки передаются по значению: функция работает с копией. Массивы и объекты — по ссылке: функция видит и меняет **тот же** массив или объект.

```glass run
fn bump(n: int) -> int {
    n += 1
    return n
}

fn fill(xs: [int]) {
    xs.append(1)
}

fn main() {
    let k = 5
    print(bump(k), k)
    let a: [int] = []
    fill(a)
    fill(a)
    print(a)
}
```

```output
6 5
[1, 1]
```

## Типы проверяются до запуска

Неверный тип аргумента — ошибка компиляции, программа даже не стартует:

```glass error
fn add(a: int, b: int) -> int {
    return a + b
}

fn main() {
    print(add(1, "2"))
}
```

```output
1 ошибок типизации (тела функций):
  6:18: тип 'string' не совместим с ожидаемым 'int'
```

## Каждая ветка должна вернуть значение

Если у функции есть `-> тип`, то `return` обязан встретиться на **каждом** пути выполнения — иначе на «пропущенной» ветке функция вернула бы `null`. Компилятор проверяет это до запуска:

```glass error
fn pick(x: int) -> int {
    if x > 0 {
        return 1
    }
}

fn main() {
    print(pick(5))
}
```

```output
1 ошибок типизации (тела функций):
  1:1: не все ветки функции 'pick' возвращают значение типа int: после последнего оператора выполнение может дойти до конца без return
```

Исправить можно по-разному: поставить `return` после `if` или добавить `else`.

```glass run
fn pick(x: int) -> int {
    if x > 0 {
        return 1
    }
    return 0
}

fn sign(x: int) -> int {
    if x > 0 {
        return 1
    } else if x < 0 {
        return -1
    } else {
        return 0
    }
}

fn main() {
    print(pick(5), pick(-5))
    print(sign(7), sign(-7), sign(0))
}
```

```output
1 0
1 -1 0
```

Компилятор не вычисляет условия, а смотрит на форму кода — так же, как проверка «can complete normally» в Java и C#. Путь считается завершённым, если на нём точно будет `return` или `throw`:

- `return` и `throw` завершают путь;
- блок завершает путь, если его завершает хотя бы один оператор;
- `if` завершает путь, только когда у него есть `else` и обе ветки завершают путь (цепочка `else if` — тот же случай);
- `while true` без `break` — бесконечный цикл, после него возвращать нечего. Любой другой `while` и `for` могут не выполниться ни разу, поэтому после них нужен `return`;
- `try` завершает путь, когда его завершают и тело `try`, и все `catch`-блоки (или когда его завершает `finally`).

Функции без `-> тип` и конструкторы эта проверка не касается. Вызов функции, которая всегда бросает исключение, путь не завершает: после него всё равно нужен `return` или `throw`.
